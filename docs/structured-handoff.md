# 结构化专家交接与短答

2026-11-17实现。保持主Agent与network/course/sales三个专家，未增加核验Agent；最终正文仍由主Agent流式生成。

## 实现

网络与课程专家通过LangChain ToolStrategy返回Pydantic结构，不再直接交付长报告。每条事实含subject（自家课程/竞品课程/竞品平台）、entity、field、value、applicability（现行/历史/未确认）、conditions及supports。每个support绑定当前调用取得的证据ID与逐字原文；unknowns独立记录本次未取得的字段。

应用中间件检查来源类别、当前专家实际取得的编号、原文摘录是否位于可见片段、内部课程编号与角色范围。网页仅校验模型所见前6000字符，不能拿存储快照的未展示部分作支持。失败项被过滤，保存specialist_handoff事件并标记PARTIAL；被拒绝字段的文字不交给主Agent，避免错误日期或对象再次进入回答。

销售专家只选择并调用工具；SalesResult要求facts与unknowns为空，应用从实际ToolMessage提取月度、渠道或自定义查询表格。金额、月份、日期边界与SQL证据编号直接传给主Agent；表结构口径作为独立metric_rules，不能冒充SQL结果事实。销售自定义查询的语义正确性仍需复核。

主Agent收到结构化事实后按当前问题回答，保留对象、历史状态与“通常”等限制。正文去掉空白和引用编号后计字符；显式“300字/400字”等优先，否则简短问题默认650字符、综合默认1000字符。超限最多额外调用一次主模型压缩，目标留出余量；保留流式增量并先重置旧草稿。压缩后仍超限时保留全文并标PARTIAL，不截断句子。来源附录及服务自动追加的状态/合成资料说明不计模型正文上限。

完整交接保存在任务事件API中，answer_revision和answer_quality记录是否压缩及最终长度。single模式仍为单Agent直接使用工具，只有篇幅控制，没有子Agent交接；offline演示保持固定流程。

## 实际边界

原文摘录存在，不代表value推理一定被原文支持，也不保证主Agent逐句引用正确。本轮已改善篇幅与角色交接，但上述三份回答仍有细节缺口，不能称为语义全部通过。现行/历史标签由模型提取，应用尚不能自动判断所有班期语义。

尚需将口径引用与查询引用分开，并进一步约束方式/服务的扩展推断及主Agent引用定位；不以关键词补丁冒充通用语义核验。本轮未重跑全部15题，保留旧轮记录，不把不同版本结果拼成准确率。自家课程与销售仍为合成验证资料。

后续r6/r7已实现Q/M分离、有限方式/服务词边界检查及一次回答修订；最新49项测试和实际剩余问题见 [引用边界收尾](evidence-boundaries.md)。本文以上保留r4/r5历史记录。
