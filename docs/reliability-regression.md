## 改了什么

| 原问题 | 修复 |
|---|---|
| 三句话要求下仍先单独写“适合。”，修订提示另有“2至4句” | 移除冲突的句数建议，要求适配结论与基础合并；补充“两句话”解析 |
| 课程名引号被当成逐字引语 | 仅将已通过专家交接、名称完全匹配的对象视为标签；其他引语仍检查原文与就近引用 |
| “没有保过承诺”被判成正向承诺 | 补充否定极性表达，保留正向承诺、无依据否定和相邻正向服务的反例检查 |
| 字段未知被写成“仅取得平台级说明” | 交接中加入实际正文/摘要片段计数，有限检查拦截资料范围扩大和与已取得正文矛盾的表述 |
| 首尾部分月份直接与完整月按总量排名 | 使用月表的真实起止边界识别部分月，针对明确命名月份的总量比较触发修订；补充提示约束 |
| 网关健康正常但真实检索失败仍提交模型任务 | 验收脚本先做真实 RAG 检索及所需销售查询，失败时保存预检状态，在提交模型任务前停止 |

修订仍最多一次，复用原证据，不截断最终正文、不自动换引用。篇幅与语义约束仍可能失败，无法通过规则证明任意自然语言结论正确。

## 如何复现

完整在线回归需先恢复外部 RAG / Milvus，再使用新的输出目录。旧结果不要混写。

```powershell
# 会做真实数据路径预检，再提交三道已知回归题；会产生模型及搜索费用
.\.venv\Scripts\python.exe scripts/acceptance_15.py --mode live --catalog examples/acceptance_fresh_6.json --ids H01,H03,H06 --output data/acceptance/new-regression
```

只回放主模型整合（同样收费，不能代替检索验收）：

```powershell
.\.venv\Scripts\python.exe scripts/replay_synthesis.py --live --records data/acceptance/fresh6-20261117-r13/H01.json --output data/acceptance/new-synthesis-replay
```

原始运行记录在本机被忽略的数据目录中，不随仓库发布；其他使用者需要先生成自己的真实任务记录。当前优先恢复真实检索，随后处理未问字段和未知对象范围，再以冻结版本验证独立新题。
