# 固定15题验收

最新完整轮次为 [r8固定版本验收](final-acceptance.md)：12道真实任务5道SUCCEEDED、7道PARTIAL；开发复核2道pass、8道needs_fix、2道fail；3道本地异常验证通过。以下保留历史轮次记录，不覆盖原始回答、不拼算通过率。

题库：`examples/acceptance_15.json`。每类3题：课程、竞品、销售、综合、异常。前12题调用真实模型和相应来源，后3题使用隔离临时数据及脚本桩，验证故障行为，二者分别报告。

## 复现

先启动课程网关及live调研服务，确保MySQL、模型、Tavily配置可用。

```powershell
# 默认只跑3条本地异常题，不调用模型
.\.venv\Scripts\python.exe scripts/acceptance_15.py
# 全部15题：12次真实模型任务，会产生模型、检索与搜索费用
.\.venv\Scripts\python.exe scripts/acceptance_15.py --mode all
# 修复后只复测指定题，必须保存到新目录
.\.venv\Scripts\python.exe scripts/acceptance_15.py --mode live --ids S03 --output data/acceptance/my-recheck
```

每题180秒超时后取消，不自动重跑。运行目录保存题目及代码SHA256、立即返回的task_id、报告、证据、事件、SQL重放、独立Decimal参考。已存在的题目文件不会重新提交；代码或题目哈希改变时拒绝混用同一目录。中断后可按已存task_id从任务接口恢复记录，不能盲目重新付费提交。

题目属于开发验收集，可用于修复；不是未见过的留出集。联网结果随时间改变，即使题目和代码固定也不能认为输入完全一致。没有单/多Agent对照，因此不支持多Agent效果提升的结论。

## 判定方法

- 工程检查：任务状态、来源范围、实际引用的来源类别、SQL重放一致性。
- 独立统计参考：直接从sales-source.json用Python Decimal计算，不调用被测SQL。数字出现仅作排查提示，不能证明数字位于正确月份/字段。
- 逐项语义核对：由Codex阅读保存的回答与引用片段，逐个检查课程字段、现行/历史班期、平台/课程承诺及销售表格；属于开发者复核，不是第三方人工盲评。
- pass代表该题关键验收要求满足，needs_fix代表核心部分可用但存在超范围、证据边界或篇幅问题，fail代表关键统计错误或任务不完整。SUCCEEDED不直接等于pass。

## 已做工程修复

1. 新增sales_monthly：按请求日期建立月份骨架，各月分别查询收款、退款，以Decimal相减，保留空月和仅退款月，首尾按实际日期裁剪。每月提供两条真实SQL证据；不让模型随意选择成交月份做左表。
2. 新增sales_channels：仅按当前课程与区间统计渠道成交数和收款，避免简单问题额外拼接退款导致口径或分组错误。自定义SQL仍可用于下钻，其语义不保证自动正确。
3. 只将已取得的真实裸证据编号格式化为方括号，不补造证据或改变结论；虚构编号继续拒绝。任务来源齐全但未引用某路时标PARTIAL。
4. 主Agent任务输入只保留课程编号和名称；去掉可被抄作证据的价格课时。提示纯network/sales不得补写未检索课程数字。
5. 提示明确平台说明、历史班期、截断摘录的适用范围；不把“已展示片段未见”说成“全页没有”，收紧超范围下钻和篇幅。
6. SQLite连接显式关闭，避免Windows临时测试库文件句柄占用。
