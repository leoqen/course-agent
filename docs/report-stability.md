# 销售表直接呈现与冻结新题验收（2026-11-20）

主 Agent 不再负责把销售查询结果抄成表格。实际执行的月度、渠道和自定义 SQL 结果由程序记录；`report_tables.py` 从原值生成 Markdown，逐行附本次查询编号，主 Agent 保留课程比较和必要解释职责。金额仍由 SQL/Decimal 工具计算，呈现层不重新计算、不舍入、不自动补引用。

## 执行与流式

1. 销售工具取得并登记实际查询结果，同时保存本任务的表格结构与证据编号。
2. 专家交接告知主 Agent 表格已占多少字符、正文剩余预算。最终使用一次 `[[SALES_TABLES]]` 标记销售表位置；标记属于内部协议，不显示给用户。
3. 流式转换器可跨模型分块识别标记并插入当前查询表；课程说明与解释继续流式输出。重写会 reset，断线重连从 SQLite 草稿与游标恢复。
4. 完整回答的字数、句数、引用边界仍检查一次，最多修订一次。表格同样计入字数；标记遗漏/重复、模型重复撰写销售表会触发修订，未解决保留 PARTIAL，不截断内容。
5. 保存的最终 Markdown 是界面、SSE 最终快照及 MD/PDF 导出的共同来源；导出不重复调用模型。

没有把“所有销售分析”变成固定模板：专家仍需选择查询工具与调查步骤，主 Agent 仍负责解释。常用统计表的数字与引用可确定呈现，不证明自由文本中的所有数字推理正确。单 Agent 对照模式也使用相同呈现层，不据此宣称多 Agent 更准确。

自定义 SQL 展示实际列名、null→未知及截断标记，不能将任意查询结果统一解释成渠道收入。重复执行同类月度/渠道工具以最新证据替换同形表，不重复堆叠。课程/网络查询不插入销售表。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe scripts/acceptance_15.py --mode live --catalog examples/acceptance_release_5.json --output data/acceptance/new-development-run
```
